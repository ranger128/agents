# ranger's docker agents

a collection of different types of agents

general notes:

- an agent whos job can be decomposed into input -> output (coding agents, task agents) are better off as single agent systems with a fresh context reviewer agent looking at the output.
- style guidelines: docker agents are already basically styled via yaml, but it would make sense to set up tooling and standards for them since its a personal repo. maybe they pull their model list or mcp servers from a pinned folder in this repo or something
